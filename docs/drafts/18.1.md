## Why

"Where does this argument's value come from?" is the question a reviewer asks before trusting a call, and the one
taint analysis (the next item) is built on. Joern, GitNexus, narsil-mcp and CodePrism answer it with a program
dependence graph and slices. Verinoda's graph has calls and imports between symbols, nothing inside a function:
the agent reads the function and guesses which assignments and branches matter. Done when: a slice answers
"where does this argument's value come from" with its lines.

## Decisions

- **New command `verinoda slice PATH:LINE [--var NAME] [--arg N|NAME] [--forward] [--depth N] [--json]`**
  (module `verinoda/slicing.py`), Python only, computed from the file as it is now (no index needed inside a
  function; the index is read only to follow callers). CLI only: no MCP tool. `PATH` is relative to the project,
  else to the working directory, and must be inside the project.
- **A control-flow graph per function, statements as nodes.** A compound statement is its header (an `if`'s test,
  a `for`'s target and iterable, a `with`'s items, an `except`'s type and name, a `case`'s pattern and guard).
  Edges follow `if`/`elif`/`else`, `while` and `for` with their `else` and `break`/`continue`, `return`, `raise`,
  `with`, `match`, and `try`: an exception raised before or after any statement of the body reaches each handler
  (and `finally`), and every way out of the body, the handlers and `else` - falling through, `return`, `break`,
  `continue`, an exception - runs `finally` and then goes on to its own target (one copy of the block per target,
  shown as one line). Nested functions and classes are one statement that defines their name and reads their
  decorators, defaults and bases, and the names their body reads without binding them itself (`nonlocal` names
  included, `global` ones not).
- **Definitions and reads.** A name assigned (`=`, annotated, augmented, `for` and `with` targets, `except ... as`,
  imports, walrus, `case` captures) replaces earlier definitions, and so does `del x`; `x.a = v`, `x[i] = v`,
  `del x[i]` and a method called on a name as a statement (`items.append(v)`) update `x` - they define it without
  replacing what it held, and read it. Names a comprehension or lambda binds for itself are not reads of the
  function's names.
- **Reaching definitions** by an iterative data-flow analysis over bit sets (one bit per definition), solved in
  reverse postorder; **control dependence** from post-dominators (bitsets solved in postorder, each node's
  immediate post-dominator found by its set, then each branch edge walked up the post-dominator tree), so a
  statement after an `if` that returns or raises depends on that `if`, and a loop body on the loop's test. A node
  that never reaches the exit (inside `while True` with no way out) depends on nothing.
- **Backward slice:** from the criterion's reads (`--var`: one name read or defined there - for `a, b = x, y` the
  `x` for `a`; `--arg`: the names of one argument of the outermost call on the line, by position or keyword, not
  with `--var`; default: every name it reads), the definitions that reach them, their reads in turn, and the
  branches every node in the slice depends on. A name with no definition in the function (module, builtin,
  closure) is listed, not guessed. A line of a nested function's decorators or `def` header is that definition in
  the function around it.
- **Across callers:** when the slice reaches a parameter, the index's `calls` edges into the function (found by
  name and definition line; by name alone, with a note, when the index is older than the file) give its call
  sites; the call of that name at the cited line is read, the parameter mapped to its argument (keyword first,
  then position; `self`/`cls` is the object before the dot, except for an instance method called through its
  class, `Cls.m(obj, x)`; `*args` or `**kwargs` that may carry it make it unknown) or to its default value, and
  that argument sliced in the caller - up to `--depth` calls up (default 2, at most 3) and 8 call sites per
  parameter. A call site that cannot be read is listed with why (`unknown`), never dropped.
- **Forward slice (`--forward`):** from the definitions at the line, every node they reach and are read at,
  transitively, and the nodes a predicate among them controls, nested branches included.
- **Output:** each line with its role (`criterion`, `def`, `control`, `use`, `controlled`), the names it defines
  and reads, and the data (definition -> read, with the name) and control edges. Status `strong_inference`: the
  lines are read from the source, the dependence between them is the analysis's (the heap is approximated), never
  an observation. Exit 2 for a line outside a function or the project, a file that does not parse, a name or
  argument not on the line, or `--var` with `--arg`; a function over 4,000 graph nodes is not analysed.
- **Review round.** An exception carried the state after the statement that raised it (`result = None; try:
  result = compute()` lost the `None`): a node at the start of the body now leads to the handlers too. `return`,
  `raise`, `break` and `continue` in a handler or `else` skipped `finally`: every way out is now routed through a
  copy of the block. A nested class body was not read, and a nested function's own locals counted as reads.
  `--forward` followed control one branch deep; `--arg` took the innermost call on the line; `Acct.take(a, raw)`
  dropped `a` as if it were the object; a default was reported where `**kwargs` may pass the value; a decorator or
  `def` header line of a nested function was "no statement"; `slice ../out.py:N` read a file outside the project
  and a path relative to the working directory was not found. Reaching definitions ran against the program order
  and post-dominator sizes were recounted per pair: 9 s on the largest function of this repository, 26 s near
  the node limit. Also: `del`, `--var` on a tuple assignment, `--var` with `--arg` refused, a line listed once
  when it holds several nodes, a note that `Cls(...)` calls are not followed to `__init__`.

## Measured

On this repository, the main checkout's index (graph loaded once, 1.7 s warm), backward slices of the last
`return` of large functions with callers followed to depth 2, before and after the review round:
`project_index/cli.py` `dispatch_command` (3,779 lines, 2,260 graph nodes) 38 slice lines in 0.5 s (9.4 s
before; at depth 0, 0.33 s against 9.04 s, and 2.0 s for `verinoda slice` end to end); `review.review` (228 lines)
126 slice lines and 67 caller slices in 2.1 s (2.4 s); `review._guard_diff` (195 lines) 83 lines, 2.1 s (2.6 s);
`analysis.analyze` (237 lines) 139 lines and 31 caller slices, 4.0 s (4.1 s). The analyses alone on
`dispatch_command`: reaching definitions 0.01 s (9.52 s), control dependence 0.02 s (0.65 s). A generated function
of 538 nodes: reaching definitions under 0.01 s (6.26 s); one of 3,964 nodes: control dependence
0.03 s (25.9 s). Every function under `verinoda/` (7,861): graph, analyses and a backward slice of each `return`
in 20.1 s in all, 0.14 s at most. On the test project the done-when holds: the second argument of
`db.execute(...)` in `save` is traced to `amount` in `checkout` (its `= 0`, the loop over the cart,
`+= price_of(...)`, the `if not cart: raise` that decides the call) and on to the `cart` that `handler` reads from
the request.

## Limits

- Python only; one function at a time plus its callers' arguments: a value returned by a called function is a read
  of that call's names, the callee's body is not entered.
- The heap is approximated: aliasing (`b = a; b.append(x)` does not update `a`), attributes as separate locations,
  globals or attributes changed by other functions, `exec`/`eval`, `getattr` and `setattr` are not seen. A nested
  function assigning a `nonlocal` name does not define it for the function around it.
- Exceptions raised inside called functions are not followed; any statement of a try body may reach its handlers
  and `finally`, any statement of a handler or `else` its `finally`. Matching an `except` type and leaving a
  `with` block are not taken to raise.
- Callers come from the index (an INFERRED edge is a resolver's guess; its confidence is shown per hop) and are
  matched by the callee's name at the cited line; a call through a variable or `functools.partial` is not found,
  nor `Cls(...)` as a call of `__init__`. An instance method called through its class is recognised by the class
  names defined in the callee's or the caller's file.
- The edges list every definition-read pair: a name with many definitions that each reach many reads makes it
  large (the generated 3,900-node function in the tests: 1.7 million edges, 5.9 s).
- No query over the dependence graph yet (taint, the next item, builds on it); no CFG or PDG export.

## Upgrading note

New command `verinoda slice PATH:LINE` (`--var`, `--arg`, `--forward`, `--depth`): a backward slice of a Python
line inside its function, across callers' arguments via the index, or a forward slice. Nothing to migrate.

## Tests

`tests/test_slicing.py`: a return's definitions and the early-return branch it depends on, a list built in a loop,
one argument of a call sliced alone, a forward slice, control-flow forms (try/except, with, while/break, match,
walrus, comprehensions), errors, a parameter followed two callers up on a scanned project, keyword/method/default
mapping and the no-index note, and the CLI. From the review round, each scenario's slice line for line: the state
before a raising statement reaching a handler (`except`, `except*`, `finally: return`), `raise`/`return` in a
handler and `return` in `else` running `finally`, a nested class body and a nested function's own names,
nested branches in a forward slice, `--arg` on the outermost call, decorator and header lines of a nested function,
`del`, `--var` on a tuple assignment, `--var` with `--arg`, a one-line `if`, `Cls.m(obj, x)`, `**kwargs` and the
`__init__` note on a scanned project, CLI paths outside the project and relative to the working directory, and
two timings: reaching definitions on 1,800 nodes and the analyses on 3,900 (each under 3 s; before, 6.3 s for
reaching definitions on 538 nodes and 26 s for control dependence on 3,964).
