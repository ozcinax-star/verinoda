# Draft: filter syntax in `query` (backlog 3.4)

Written for the merge. The D-number is assigned then (the next free one after D71); the code cites the design
section by its title, "Filter syntax in a query", and should be switched to the D-number when this lands in
`docs/DESIGN.md`.

## Findings that drive the design

- `verinoda query` and MCP `project_query` took one free-text question. The only ways to narrow them were words
  the ranker happens to weigh (a path written in the question scores x2.0, D40) and `include_tests`, which the
  CLI does not expose. "The retry logic, but only in Kotlin", "only under `src/main`", "not the vendored copy",
  "every line that matches `TODO\(`" could not be asked.
- GitHub code search and Sourcegraph write this as filters inside the query string (`path:`, `lang:`,
  `symbol:`, `is:`, `/regex/`, `AND`/`OR`/`NOT`). Agents already know that syntax, so it goes into the same
  `question` argument: no new MCP tool, no new CLI flag, and the core profile stays at five tools.
- Every unit the search index holds already has its file, kind, name, qualified name and line span
  (`search_index.Handle.units`, `units.qual`), and the extractor already decides what is vendored, minified or
  generated (`project_index.vendored.vendored_reason`, D65). No index change is needed.

## Decisions

- **Where it is read.** `verinoda/query_filters.py` parses the question; `retrieval.retrieve(..., filters=True)`
  applies it. Only `verinoda query` and `project_query` pass `filters=True`. `analyze`, the UI, `research` and
  the benchmarks pass their question through as before, so filters never change what they rank.
- **A question with no filter atom is not parsed.** Filter atoms are `key:value` with a known key, or a
  `/regex/` token. Without one, the question is ranked exactly as written: an upper-case `OR` or `NOT` in prose
  stays a word, and every existing question gives the same result.
- **Atoms.**
  - `path:` (alias `file:`): a glob (`*`, `?`, `[..]`) matches the whole repository path from the root, `*`
    crosses folders, and `**/` also matches no folder. A plain value matches from the root or after any `/`
    (`path:search_index`, `path:tests/`). Case-insensitive.
  - `lang:` (alias `language:`): by suffix. It knows common names and aliases (`py`, `kt`, `ts`, `js`, `jvm`
    = Java/Kotlin/Scala/Groovy, ...). An unknown name is taken as a suffix (`lang:mcfunction`).
  - `symbol:`: a symbol unit (not a module block, prose section or data unit) whose name or qualified name is
    the value, or ends in `.value` (`take`, `PriceCache.take`), or matches it as a glob (`symbol:test_*`). A
    non-glob value is also added to the ranked text, so D40's exact-identifier boost ranks the symbol first.
  - `is:vendored` (vendored, minified or generated), `is:generated`, `is:minified`, `is:test` (`is_test_file`,
    D40). An unknown `is:` value is an error.
  - `/regex/` and `/regex/i`: Python syntax, matched line by line over the unit's span. A token with an
    unescaped `/` inside (`/api/users/`) is a word, so a URL path in a question is not a regex.
- **Boolean logic.** Atoms side by side are ANDed. `OR` joins alternatives, `NOT` or a leading `-` negates, and
  parentheses group. `AND` binds tighter than `OR`, as in GitHub. A plain word beside an operator (`cache OR
  memo`, `NOT legacy`) becomes a content atom: a line of the unit holds it as a case-insensitive substring, so
  `legacy` also meets `price_of_legacy`. The words stay ranked text unless they are negated. Every other plain
  word is only ranked text.
- **Filters combine with the ranking; they do not replace it.** `search_index.rank` takes a `where` hook. The
  whole ranking (BM25F, the graph prior, tests yielding) runs on the text as before. The hook then keeps the
  subset the filters accept, before the order is taken and the limit applied, so the kept units stay in their
  ranked order and the 60-unit limit counts only kept units. Filters never add score.
- **A question of filters only** (for example `/TODO\(/ lang:py`) has no ranked text. Every indexed unit is
  then a candidate at score 0, and the matching ones come in path and line order. The same happens when the
  text matched nothing.
- **Evidence.** A unit kept by a regex or word atom carries `regex /x/ at file:N` (or `word 'x' at file:N`) in
  its `why`. Its excerpt (JSON) and its first text window are centred on that line. Other atoms are exact
  predicates on the path, suffix, name or vendored rule, and the result's `filters` block states them.
- **Output.** JSON gets a `filters` block, `{"expression", "ranked_text", "matched"}`. `expression` is the
  expression as read, `ranked_text` what was ranked, and `matched` the number of candidates the filters kept.
  The block is charged to the budget. Plain text opens with `filters: <expression> (N matching)`, or
  `filters: <expression> - no indexed unit matches them`. A query result is still a list of leads, not claims,
  as before.
- **Errors.** A bad regex, an unknown `is:` value, or a dangling `OR`/`NOT` raises `FilterError`. The CLI prints
  `error: ...` and exits non-zero. MCP returns `{"error": "invalid_argument", "message", "hint"}`, and the
  hint lists the syntax.
- **MCP exposure.** `project_query` is one of the core five and already takes the question, so there is no new
  tool and no `run_tool` entry. Its `question` argument description names the filters (one line).

## What was built

- `verinoda/query_filters.py` (new): tokenizer, parser (`parse` -> `Filters | None`, `FilterError`), matchers
  (`path_matches`, `lang_matches`, `symbol_matches`) and `Selector`, the `where` hook.
- `verinoda/search_index.py`: `rank(..., where=None)`, with the filter step before ordering, and
  `Hit.match_line`.
- `verinoda/retrieval.py`: `retrieve(..., filters=False)`, the `filters` block, excerpt focus on the matched
  line, and the `filters:` line and matched-line window in `render_text`.
- `verinoda/cli.py`: `query` reads filters, and the `question` help lists them. A `FilterError` is
  `error: ...`.
- `verinoda/mcp/server.py`: `project_query` reads filters, a `FilterError` becomes `invalid_argument`, and the
  argument description is extended.
- `tests/test_query_filters.py` (new, 20 tests).
- `README.md`: the `query` command row names the filters, and the examples gain a filtered query.
  `docs/ARCHITECTURE.md`: a `query_filters.py` module row (required by `tests/test_docs.py`).

## Limits / not done

- A regex matches one line at a time. Multi-line patterns, and patterns across a unit boundary, are not
  supported. A regex over a filters-only question reads every indexed file once (through the cached line
  reader). There is no trigram index (backlog 1.7).
- Filters see what the search index holds. Files the index skips (too large, binary, lock files, bulk data) are
  never matched, and a `path:` that names only such files matches nothing.
- `symbol:` matches the unit's own name and qualified name as the index stores them (`Class.method`). It does
  not use the module path (`pkg.mod.func`); combine it with `path:` for that.
- Nested units (a class and its methods) each match a regex on a shared line. The same-text folding of the
  result keeps this small, but both can appear.
- `is:vendored` follows the extractor's rules, not the project's `.gitignore` or `linguist-vendored`
  attributes.
- `-word` (a negated plain word) is not a filter: `-` negates only an atom. Write `NOT word`.
- A value with spaces needs quotes only for `key:"..."`. Regexes may contain spaces (`/TODO: round/`).
- `include_tests` is not exposed on the CLI. `NOT is:test` covers it.

## Upgrading note

`verinoda query` and MCP `project_query` read filters in the question: `path:GLOB`, `lang:NAME`,
`symbol:NAME`, `is:vendored|generated|minified|test`, `/regex/`, and `AND` / `OR` / `NOT` / `-` / parentheses.
Filters narrow the ranked results and add no score. A question of filters only lists every matching unit. A
question with no `key:value` filter and no `/regex/` token ranks exactly as before. JSON results with filters
carry a new `filters` block. An unreadable filter is an error: exit code 1 on the CLI, `invalid_argument` on
MCP. No re-index is needed.
