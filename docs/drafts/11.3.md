# 11.3 Background consolidation (draft for DESIGN.md; next free D-number)

## Why

Letta's sleep-time agents and Cognee's memify tidy an agent's memory between sessions. Verinoda's claims go stale
when the code behind them changes and stay stale until someone runs `verify`, even when the change was undone;
and two analyses can record the same statement twice.

## Decisions

- **`verinoda consolidate [--limit N] [--budget S] [--merge] [--dry-run]`**, CLI only.
- **Stale claims are re-verified** with `verify` (static: cited lines and the files behind each claim) on the
  current tree, newest first, at most `--limit` (50) within `--budget` seconds (60): one whose code is back as
  it was, or whose cited lines re-check, is restored up to its recorded ceiling and rebound to the current
  snapshot; the rest stay stale. No test is run: `verify --run` stays the user's call. One claim failing never
  stops the others (it is listed, exit 1).
- **Duplicates.** Claims with the same claim key (kind and semantic spec, subjects, else the normalised text)
  that are not superseded and not already folded form a group. `--merge` keeps the one with the best status,
  then the latest verification, and folds each other one into it: its evidence is linked to the kept claim
  (note `merged from`), the kept claim is re-assessed with the union, and the duplicate keeps its row and
  status with `spec.duplicate_of` and a history entry naming the kept claim. Nothing is deleted, and a folded
  claim is not marked superseded (that would make it contradicted).
- **In the background.** `update --consolidate`, or `claims.consolidate_on_update: true` in
  `.verinoda/config.json` (off by default), runs it after a successful update with 20 claims and 20 s, and
  reports the counts; so the updates the git hooks and `ui --watch` start re-check stale claims too. A failure
  there never fails the update.

## Measured

Tests only.

## Limits

- Only stale claims are re-verified; a claim that is merely old is not re-checked.
- Duplicates are exact on the claim key: two wordings of one fact are not found.

## Upgrading note

New: `verinoda consolidate` re-verifies stale claims against the current tree and finds duplicate claims
(`--merge` folds them, nothing deleted); `update --consolidate` or `claims.consolidate_on_update` in
`.verinoda/config.json` runs it after each update. The MCP tool count is unchanged.

## Tests

`tests/test_consolidate.py`: a stale claim stays stale while its code differs and is restored when the code is
put back (a dry run changes nothing); the limit and the time budget; two claims with one statement are folded
(evidence linked, the duplicate marked and not superseded, the group gone) and another claim untouched;
`update` consolidates only with the setting (and the flag); the CLI.
