# 19.4 Regression test generation (opt-in): `verinoda pin`

## Why

Before a refactor, an agent (or a person) wants tests that hold the code's current behaviour, so that a change in behaviour shows up as a failing test rather than as a surprise later. Pynguin-style search generates inputs and needs a heavy dependency; the project's own tests already call the function with inputs someone chose on purpose. `verinoda pin FUNCTION` records those calls while the tests run and writes them as a plain pytest file. The file needs neither Verinoda nor any new dependency. A test is kept only when it passes again on a fresh copy of the tree.

The backlog row is done when a generated test passes on the current tree. Here every written file has passed a run of exactly its content on a copy of the working tree, and that run backs an `experiment_verified` claim.

## Decisions

- **Recorded, not generated.** The inputs are the arguments the selected tests passed. No search and no Pynguin; Hypothesis is not used either.
- **Test selection.** In order: the tests the test-to-code map saw run the function (rows of earlier `observe` runs), then the tests that reach it statically on the index (`runtime.trace.select_tests`, the rule `observe --for` uses), at most 50. `--tests SELECT` replaces both. With neither map rows nor an index, nothing runs: the status is `unknown`, with a next step.
- **Same gate as every code-running path.** The recording and the replays go through `experiments.run`: trusted projects only under process isolation (else a container, else `refused` with the `verinoda trust` next step), a throw-away copy, a scrubbed environment and a tree-killing timeout. Nothing runs in the user's tree.
- **Recorder.** `runtime/pin_plugin.py` is a new standalone plugin, not an extension of the call tracer. The call tracer keeps edges and never values, and adding value capture to its hot path would slow every `observe`. The pin plugin uses `sys.monitoring` on one code object (`PY_START` returns `DISABLE` for every other one, `PY_RETURN` is local to the target, `PY_UNWIND` returns at once for other frames). It records arguments at entry, before the function can change them. Python 3.12+ only: there is no `setprofile` fallback, because `setprofile` cannot tell a return from an exception.
- **Safe literal form.** A value is kept only as source that rebuilds an equal value of the same type:
  - `None`, bool, int, float (`float('nan')`/`inf` spelled out), str, bytes;
  - tuple, list, dict, set and frozenset (set elements sorted by their source);
  - `decimal.Decimal`, `fractions.Fraction`;
  - `datetime` date, datetime and timedelta values (time zone only as `datetime.timezone`);
  - enum members by qualified name;
  - dataclass instances of project classes, rebuilt by their constructor (`init=False` fields are refused).
  The source is evaluated again (only these names are in scope) and compared by `_pin_key` (see The file). Anything else is skipped, and the call is counted under its reason (`unsupported type orders.repository.OrderRepository`).
- **Methods.** Plain functions, static methods and class methods are supported; a class method is pinned only when called on its own class. An instance method is supported only when `self` is a rebuildable dataclass instance of the class itself. Any other method is refused before anything runs. Generators, coroutines and test code are `unsupported`.
- **Exceptions** are pinned by exact type (`pytest.raises` plus `type(...) is`) and by `str()` message. Types must be importable by name and not defined in test code. A message that holds a memory address or the copy's directory is skipped.
- **Dedupe and determinism.** Calls are deduplicated by their call source. An input seen with two different results in the recording run is dropped (`different results for the same input`). The generated file then runs once in a fresh working-tree copy, added through a new `experiments.run(add_files=...)` option. Tests that fail there are dropped as nondeterministic. When any were dropped, the file with only the kept tests runs once more, so a written file has always passed a run of exactly its content.
- **The file.** The default is `tests/pinned/test_pin_<module path>__<qualified name>.py` (`test_pin_orders_pricing__apply_discount.py`), so functions of one name in two modules get two files. `--out` must be a plain path inside the repository: no hidden folder (`.venv`, `.github`), and no symbolic link or junction on the way; the resolved path must stay inside. An existing file is refused without `--force`; with `--force` only a file whose first line is `# Generated by verinoda pin` and whose `# Regenerate:` line names the same function is replaced. These checks happen before anything runs and again right before the write, which creates a new file exclusively (`O_CREAT|O_EXCL`). The header names the commit, the recording copy's tree hash and the tests the inputs came from. Each test names the test that produced its input. Results are compared by `_pin_key`/`_pin_same`, copied verbatim from the recorder into the file: a text built from every type and `repr` all the way down, so `1`, `1.0` and `True` differ, `0.0` and `-0.0` differ, `Decimal('3')` and `Decimal('3.00')` differ, set elements and dict keys are compared by type and value, dict key order counts, and every dataclass field is compared (also `compare=False` ones). NaN equals NaN.
- **What the recorder wrote is checked.** The recorder runs inside the project's test process, so `pin.py` checks its output before anything is rendered: the module and every import must be dotted identifiers (no dunder parts), the module must name the target's file, exception types must be builtin exceptions or names under a recorded import, and every value source must parse (`ast`, eval mode) to constants, tuples, lists, sets, dicts, unary minus, calls of `float`, `set`, `frozenset`, `decimal.Decimal`, `fractions.Fraction` or `datetime.*` constructors, calls of a class defined in the project file the import names, or an attribute or subscript under a recorded import (enum members, `datetime.timezone.utc`). A case that fails is dropped and counted (`the recorded source is not a literal value Verinoda writes`).
- **Claim.** A `test_run` claim: "FUNCTION's behaviour on these N inputs is pinned at commit X: the generated tests in PATH pass in run R". It is created through `Claims.create` with `experiment_verified` requested and the passing run's evidence as support. The claim rules grade it (the spec names the run, and the function's file is in the generated file's import closure). `--no-record` skips it.
- **Review round.** A review found that the comparison fell back to `==` below the top level (so `-0.0` to `0.0`, a lost `Decimal` quantize, `{1.0}` to `{1}`, `{1.0: v}` to `{1: v}` and a `compare=False` dataclass field all passed the pinned tests), that `--out` through a junction wrote outside the repository, that the recorder's JSONL was pasted into the file unchecked (a project `conftest.py` could rewrite it and inject an `import os; ...` line into the user's tree), and that the default name ignored the module while `--force` replaced any `.py` file. All four are fixed as described above, with tests for each (the five value mutations fail the generated file; a junction, a production module and another function's pin are refused before anything runs; a tampered recording writes nothing). Also: a call whose arguments share a mutable object (`alias(a, a)`) is skipped as `arguments share an object` instead of being dropped on replay under the wrong reason; dict key order is pinned; when tests failed in the recording run, the headline, the next step and the claim text say so; and the default selection leaves out every file under `tests/pinned/`. The earlier text here said types were compared all the way down; that was true only for lists, tuples and dict values.
- **No MCP tool.** `change_probe` returns its tests as text and writes nothing. `pin` writes into the working tree and runs the tests twice, so it stays a CLI command. The tool count stays 44, and the core menu is unchanged.

In an untrusted project nothing runs and nothing is written.

## Limits

- A pin is what the function did on the inputs the selected tests gave it at one commit. It is not a specification: a pinned bug stays pinned, and other inputs are not covered.
- Only return values and raised exceptions are pinned. Side effects, the arguments' state after the call, output and logging are not.
- Values outside the allow list (most objects, callables, file handles, numpy arrays, tz-aware datetimes with non-`datetime.timezone` zones, dataclasses with `init=False` fields or no value equality) are skipped. Calls whose arguments share a mutable object are skipped too. Functions whose inputs are such objects (`place_order(repo, ...)`) pin nothing, and say why.
- Python 3.12+ for the project's interpreter (`sys.monitoring`). Calls in child processes started by tests are not seen.
- One replay decides what is kept: a result that changes rarely can still pass it. Every run pins `PYTHONHASHSEED=0`, so an order that depends on string hashing looks stable.
- A method is pinned only on a dataclass `self`. A class method called on a subclass, nested functions and lambdas are skipped or unsupported. Exception messages are compared exactly.
- Dict key order is part of the pinned result. A dict built from a set of strings has a hash-dependent order: it is stable in Verinoda's runs (`PYTHONHASHSEED=0`) but the pinned test can fail when pytest runs with another seed.
- Two different functions can still map to one default name when module and function names contain `_` (`pkg/a_util.py` and `pkg_a/util.py`): the second is refused (the header names the other function), not replaced; pass `--out`.
- Calls of project classes in recorded sources are allowed when the class is defined in the project file the import names; a dataclass nested in another class (`Outer.Inner`) can be dropped as not a literal value, because only top-level classes are looked up.
- Inputs recorded while a test failed are still pinned (the headline and the claim say how many tests failed).
- At most 50 tests are selected, `--max-cases` is at most 500, and the recorder keeps at most `max(200, 4 x max-cases)` distinct inputs (2,000 at most). Later new inputs are counted, not kept. The first inputs seen are kept, in the order the tests made them.
- The generated file imports the module by the name it ran under in the tests. If the project's pytest settings (`pythonpath`, `conftest.py`) do not make that name importable from `tests/pinned/`, the replay does not run, and the status is `inconclusive` with the run's log.
- Not available through MCP.

## Upgrading note

New command `verinoda pin FUNCTION [--tests SELECT ...] [--max-cases N] [--out PATH] [--force] [--timeout S] [--no-record]`. It is opt-in and runs the project's tests, so it needs `verinoda trust <path>` (or a container runtime), like `observe`. It writes `tests/pinned/test_pin_<module>__<name>.py` only after that file passed a run; `--force` replaces only a file it generated for the same function, and links, junctions and hidden folders are refused. The exit code is 0 when something was pinned, otherwise 3.

`experiments.run` gains `add_files` ({path: bytes} written over a working-tree copy and listed in `source.added`; the evidence locator says `working tree + added PATH`). The new run artifacts are `pin.jsonl` and `pin_replay.jsonl`. Nothing changes in the store schema, the MCP tools (still 44) or existing commands.

## Tests

`tests/test_pin.py`, 80 tests (16 run real child processes):
- **orders_app:**
  - the generated file passes on the current tree and backs an `experiment_verified` claim;
  - it fails after a deliberate behaviour change in a copy;
  - an existing file is kept unless `--force` is given;
  - an untrusted project is refused and nothing is written.
- **Toy project:**
  - nondeterministic inputs are dropped (one as inconsistent, one on replay) and the rest are pinned;
  - an instance method of a dataclass, a static method and a class method are pinned, and so is a function taking an enum member and a `Decimal`;
  - an `object()` argument is skipped with its reason;
  - instance methods of other classes, generators and test code are unsupported without a run;
  - `--out` must stay inside the repository;
  - `experiments.run(add_files=...)` is refused on a commit copy.
- **Value encoder (in-process):**
  - 20 supported values rebuild to equal values of the same type;
  - set source does not depend on iteration order;
  - unsupported values are skipped with a reason;
  - `same` compares types all the way down;
  - exceptions are named by an importable type and their message.
- **Review round:**
  - eight value pairs that `==` calls equal (`-0.0`/`0.0`, Decimal exponents, set elements, dict keys, a `compare=False` field, dict order, nested Decimals) differ under both the recorder's and the generated file's comparison;
  - a pinned function returning all five shapes fails its generated file after each of five mutations;
  - a junction (a symlink on POSIX) on the way, hidden folders, `:` and `..` paths are refused, and nothing lands outside;
  - `--force` refuses a production module and another function's pin; a new file is created exclusively;
  - 16 recorded cases (11 tampered: injected imports, calls, lambdas, dunders, a statement in an exception reference) are accepted or dropped as expected, and a `conftest.py` that rewrites the recording writes nothing into the tree;
  - shared mutable arguments are detected.
