# 12.2 Agent instruction file lint

Row: AGENTS.md, CLAUDE.md and memory files: paths exist, scripts and targets exist, packages declared, files
agree. Done when: each sentence that names something is checked and wrong ones reported.

## What was built

`verinoda agent-lint [--file PATH] [--no-memory] [--all] [--json]` (`verinoda/agentlint.py`, `cmd_agent_lint` in
`verinoda/cli.py`). No model, no network, read-only.

- **Files read**: AGENTS.md / AGENT.md, CLAUDE.md, CLAUDE.local.md (also when git-ignored), GEMINI.md,
  `.cursorrules`, `.windsurfrules`, `.clinerules` at any depth (not under test folders);
  `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md`, `.cursor/rules/*.mdc|md`,
  `.windsurf/rules/*.md`, `.clinerules/*.md`; Claude Code's memory folder
  `~/.claude/projects/<path, non-alphanumerics as dashes>/memory/*.md` for the checkout and, in a git worktree,
  for its main checkout (`--no-memory` leaves it out); any `--file`.
- **What a line names** (`mentions()`): Markdown links, memory `[[wiki]]` links, CLAUDE.md `@imports`, code
  spans, lines of shell fences (and plain fences, but only for known commands, so a tree diagram is not read as
  paths), and prose tokens with a folder in them. YAML front matter and HTML comments are skipped.
- **Checks**, each one record `{verdict ok|wrong|unknown, status, kind, name, at, text, why, evidence[, nearest]}`:
  - `path` / `link` / `import`: exists under the file's folder, then the repository root (a memory file: the root
    first; a link: its own folder), with the case as written; `file:LINE[-LINE]` and `#L10` within the file;
    globs match a file or folder (`**/` is any number of folders, none too; `*` stays in one folder). A wrong
    path lists `nearest`: the same tail somewhere else (a moved file) or close file names. A path outside the
    repository (an absolute one, or `~/...` outside a memory file) is `unknown`; `/x` in a link, or `/x/...`
    whose first folder the repository has, is read from the repository root (as GitHub reads a link). A
    link in angle brackets may hold spaces, and a code span with a space in it that names an existing path is
    a path, not a command.
  - `script`: `npm run X`, `npm test`, `pnpm X`, `yarn X`, `bun run X` against the package.json where it runs
    (`cd` moves it, for the rest of the line and the next lines of the same shell block; a `cd` it cannot
    follow, such as `cd -`, `cd $DIR` or a missing folder, makes what runs after it `unknown`;
    `--prefix` / `--filter` / `-C` / `-r` / `--workspaces` look in every package.json). `bun test` and
    `bun build` are bun's own runner and bundler, not scripts.
  - `target`: `make [-C d] [-f f] X` against the Makefile (a file with `include` or pattern rules makes a
    missing target unknown); `just X` against the justfile's recipes and `alias x := y` lines.
  - `module`: `python -m X` is a module of the project (root or `src/`), the standard library, or from a declared
    package (by name, strong_inference).
  - `package` / `extra` / `tool`: `pip install X`, `uv add`, `npm install X` are declared; `pip install -e .[a,b]`
    and `uv sync --extra/--group` name declared extras and groups; tools run by name (`pytest`, `ruff`, `black`,
    `npx eslint`, ...) have their package declared (strong_inference: a name-to-package table). The evidence
    is the line that declares the package (a requirement string or a TOML key), not the first line that
    mentions its name. `uv run` / `poetry run` options that take a value (`--extra dev`, `--with x`,
    `--group g`) are read as such: the extra or group is checked, and the command after them.
  - `command`: the first word is a console script the project declares.
  - `agreement`: two files that give a test / lint / format / typecheck / build command must share one (a
    script's body or a target's recipe counts, so `make test` whose recipe runs pytest agrees with `pytest`);
    the package manager a file uses must be the one the lock file (or `packageManager`) pins, or, with no lock,
    the same in every file. strong_inference, except an agreeing lock (statically_verified). Only files that
    govern the same folder are compared: a nested `web/AGENTS.md` (or `web/.cursor/rules/`) governs `web`,
    where another stack may run other commands.
- Output: text (wrong, then unknown, each with its line quoted) or `--json`; ok checks are counted, listed with
  `--all`. At most 1000 records are listed (wrong first; `truncated` and `checks_not_listed` say how many
  more), the summary counts them all. Exit 3 when something is wrong, 2 when there is no instruction file, 0
  otherwise.

## Decisions

- **Statuses**: what the tree or a manifest shows is `statically_verified`; name-to-package mapping, a module
  from a declared package, and command disagreement are `strong_inference` at most (a heuristic). A path that is
  missing but git-ignored (a build output, a local file), or on a line that says to create or write it, is
  `unknown`, never wrong. Gradle tasks and Maven goals are `unknown` (the build script defines them in code).
- **What counts as a path in prose**: only a token with a folder in it and either a known extension or a first
  folder that exists; placeholders (`<id>`, `{x}`, `$VAR`), URLs, domains, `ns:id`, options, slash commands and
  `origin/main`-style refs are not paths. A bare file name counts only in a code span or link, and is ok if the
  project has a file of that name anywhere.
- **Case**: a path found only in another case is wrong (it works on Windows/macOS disks, not on Linux or in
  git), with the spelling on disk.
- **CLI only, no MCP tool yet**: the full profile could take it (it would not touch the five core tools), but
  `tests/test_docs.py` requires README, ARCHITECTURE and UPGRADING to state the same MCP tool count, and
  UPGRADING.md is not edited on this branch; with other items in flight the count would also conflict. The
  adapter was written and tested, then taken out; it is below for the merge.
- **Outside the repository**: a per-user path (`~/.config/...`) or an absolute path outside the checkout is
  `unknown` (a record, not skipped): whether it exists depends on the machine that runs the lint, and a CI
  run must not fail on it. A memory file is this user's own notes, so its `~/...` is checked against their
  home. `/docs/x.md` is root-relative the same on every OS.
- **`cd` in a shell block** carries to the block's next lines (a block is read as one shell session); a folder
  it cannot follow makes the rest unknown rather than checked against the wrong package.json.

## Limits

- A name in plain words ("run the tests with pytest") is not read; only code spans, links, imports, fences and
  prose paths with a folder.
- Subcommands of the project's own console script are not checked.
- The tool-to-package table is fixed (Python and JS tools listed in `PY_TOOLS` / `JS_TOOLS`); any other `npx X`
  looks for a package named X.
- Makefile parsing is line-based: targets from `include`d files or `$(eval)` are unknown, not found.
- Memory files are found by Claude Code's folder naming; other agents' memory is not read.

## Review fixes

- `cd` on its own line in a shell block was forgotten on the next line, so `cd web` / `npm test` was checked
  against the root package.json: it now carries through the block.
- `pnpm -r X`, `npm --workspaces`, `-ws` look in every package.json; `bun test` / `bun build` are bun's own.
- Globs are matched as git reads them (`**/` may be no folder), not with fnmatch.
- Agreement compares only files that govern the same folder.
- Dependency evidence is the declaring line (`_dep_line`), not a substring match anywhere in the manifest.
- `~/...` outside a memory file, and absolute paths outside the repository, are unknown records; `/x` is
  root-relative on every OS (it was skipped on Windows and read from `/` on POSIX).
- `uv run` skips the values of its options and checks `--extra` / `--group`.
- `just` reads `alias x := y`.
- Paths with spaces: `[x](<a b.md>)` links, and a code span that names an existing spaced path.
- Speed: the repository and each base folder are resolved once (`Tree.rel_of`); a moved file is looked up by
  its name, not by scanning every file; the fuzzy close-name match (the slow part) runs for the first 50
  missing names only; the listed records are capped at 1000. The reviewer's 1,000-line file (3,000
  mentions) now takes about 8 s here, most of it listing the files and the one `git check-ignore` call.
