# 2.5 Rename preview

Row: every site a rename would touch, each with its evidence, without editing. Done when
`verinoda rename-preview A B` lists all sites and nothing is written.

## What was built

- `verinoda/rename_preview.py`: `run(g, symbol, new_name, stale=, max_sites=)`, `preview()`, `render()`,
  `check_new_name()`.
- `verinoda rename-preview <symbol> <new_name> [--max-sites N] [--json]` in `verinoda/cli.py`
  (`cmd_rename_preview`), with the freshness note of the other graph commands.
- README Commands row, ARCHITECTURE module row.
- `tests/test_rename_preview.py`.

Output, per symbol (resolved exactly by `naming.resolve`; an ambiguous name lists its candidates, a file or
module is `not_a_symbol`):

- `sites`: the lines a rename changes, one entry per spelling (file:line:column), each with `kind`, `status`,
  `why` and the line:
  - `definition` (`statically_verified`: the node's own line spells the name);
  - `call`: graded by `entail.call_site`, the check `analyze` uses. `statically_verified` only for an
    EXTRACTED edge whose Python line calls the name; other languages `strong_inference` (which definition a
    line binds is checked for Python only);
  - `import`: `statically_verified` for an EXTRACTED Python `from <its module> import` line, otherwise
    `strong_inference`;
  - `reference` / `supertype`: other EXTRACTED in-edges, `strong_inference`;
  - `bound`: a spelling with no edge of its own that its place ties to the symbol (inside a caller an
    EXTRACTED edge ties to it: the graph has one edge per caller and callee, so the second call in the same
    function has none; a file that imports the name; its own module, or its class for a method).
    `strong_inference`;
  - `override` / `overload`: methods of the same name in classes above, below or beside the owner
    (`inherits`/`implements`/`extends`/`mixes_in`) and overloads in the same class, with their own edge lines.
    The tie is by name, so `strong_inference` at most.
- `mentions` (`weak_inference`): spellings with nothing sure tying them to the symbol. That covers comments,
  strings, documents and reflection, plus a line that only a guessed (INFERRED) edge grading `weak_inference`
  ties to it (kind `inferred`, with the edge in `why`).
- `other_symbols` / `other_symbol_lines`: symbols of the same name outside the family and the lines the index
  ties to them. These are left alone.
- `not_spelled`: edge lines that do not spell the old name, such as a call through an import alias
  (`ct([2])`). The line keeps working after the rename, so it is not a site.
- `conflicts`: the new name is already a member of an owner class in the family, or already defined in the
  module (`statically_verified` when its line spells it). A new name already spelled in a file the rename
  edits is also a conflict (`weak_inference`: it may shadow or be shadowed, so read it).
- `counts` (sites, files, mentions, by_status), `coverage` (files read / skipped for the mention scan),
  `truncated`, `written: "nothing: ..."`.

Exit codes: 0 found, 2 when the symbol does not resolve or the new name is invalid (not an identifier, a
reserved word, the current name), 3 when there are conflicts.

## Decisions

- **Evidence, not an edit plan.** The command reads the code and the index. It writes no file, no claim and
  no index. The CLI test compares file hashes and the claim count before and after.
- **Sites carry `strong_inference` or better.** An INFERRED edge that grades no better than
  `weak_inference` is a guess. On Verinoda's own repository, renaming `when.guards` drew `indirect_call`
  edges from `self.guards = guards` and keyword arguments named `guards` in other modules. So these lines
  go to the mentions with the edge named, not to the sites: a list of lines the rename changes should not
  hold lines that a guess alone ties to the symbol.
- **Call grading reuses `entail.call_site`,** so `rename-preview` and `analyze` agree on what a verified call
  is.
- **A changed file caps its lines at `strong_inference`.** Its edges may point at lines that moved. The why
  says so and names `verinoda update`.
- **The mention scan is bounded.** It reads the files the search index says may spell the name (token in a
  passage or a unit name), every unindexed or changed file, and never generated output. The scan stops
  after 10 s and says so. When the search index is missing or describes another graph, it reads every file.
- **CLI only for now.** The MCP tool (`rename_preview`, read-only, behind `run_tool` in the core profile, so
  the core menu stays at five tools) was written and tested. It is held back because it changes the tool
  count from 37 to 38. `tests/test_docs.py` checks that count in README, ARCHITECTURE and UPGRADING, and this
  item does not edit UPGRADING.md. The wiring is in `docs/drafts/2.5-mcp.patch` (server.py and
  test_mcp.py). To merge it, apply the patch and change "37 tools" to "38 tools" in README.md (status row
  and `mcp serve` row, where `rename_preview` also joins the `run_tool` list), in docs/ARCHITECTURE.md
  (diagram and `mcp/` row) and in docs/UPGRADING.md. Also add the MCP test to tests/test_rename_preview.py:

  ```python
  def test_mcp_rename_preview(repo):
      from verinoda.mcp.server import AtlasTools

      t = AtlasTools(repo)
      res = t.rename_preview("shop/pricing.py::compute_total", "price_items")
      assert res["status"] == "found" and any(s["kind"] == "definition" for s in res["sites"])
      assert t.rename_preview("compute_total", "x")["status"] == "ambiguous"
  ```

## Limits

- Bindings come from the index, not from a type checker or language server. A Python call is verified only
  when `entail.call_site` shows the line calls the name. For other languages it is `strong_inference`.
- Keyword arguments (`f(compute_total=...)`), attribute access through `getattr`, string-built names and
  code outside the repository are mentions at best.
- An import line is not in the search index. A file that spells the name only on an import line, with no
  import edge to the symbol, is skipped by the prefilter (the coverage line says so).
- Overrides are found by name through the class edges the index has. An interface method implemented by
  name without an `implements` edge is not found.
- The "bound by place" rule marks every spelling inside a tied caller, or in a file that imports the name.
  A local variable of the same name there becomes a `bound` site (`strong_inference`, with the reason).
- A file or module rename is not previewed (`not_a_symbol`).

## Upgrading note

New command `verinoda rename-preview <symbol> <new_name> [--max-sites N] [--json]`: every line a rename
would touch, each with its status, why and the line, plus mentions, other symbols of the same name and
conflicts. It edits and records nothing. Exit 2 when the symbol does not resolve or the new name is
invalid, 3 on a conflict. No schema or index change. No MCP tool yet (see above).

## Tests

`tests/test_rename_preview.py` (11 cases):

- Python function sites and statuses: definition, import, verified call, the second call in a caller
  (`bound`), own module, alias import, and the alias call listed as `not_spelled`.
- Mentions (a string in another file), another symbol of the same name left alone with its call line,
  conflicts (a local in an edited file, a module-level name).
- Java overrides above and beside, a Java call never `statically_verified`, a sibling member conflict.
- Invalid new names (4 parametrised cases), unresolved and ambiguous names, a file.
- CLI: `--json` and text output, exit codes 0/2/3, the tree's file hashes and the claim count unchanged.
- A changed file keeps `strong_inference` at most.
- A line only a guessed INFERRED edge ties to it is a mention (`inferred`), not a site.

Run together with tests/test_docs.py and tests/test_cli.py: 121 passed (Windows 11, Python 3.12, 2026-09-30). tests/test_mcp.py is unchanged (the MCP wiring is held back).
