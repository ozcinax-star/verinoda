# Structural (AST pattern) search: `verinoda grep-ast`

## Why

Text search finds spellings; it cannot say "every call of `foo` with at least one argument" or "every `return`
of a Java method" without a regex that breaks on line breaks, comments and nesting. ast-grep, Semgrep, Comby and
Sourcegraph's structural search answer such questions with code-shaped patterns and metavariables. Verinoda
already has the tree-sitter grammars the index reads, so the same kind of search costs no new dependency.

## Decisions

- **Pattern = code with metavariables.** `$A` (an upper-case name) is one named node and captures its text; the
  same name twice must capture the same text; `$_` matches one node without capturing. `$$$REST` is zero or more
  nodes in a sequence of children (`$$$` alone: without capturing). The metavariables become placeholder
  identifiers (`VNMV_A`, `VNMVS_REST`) so every grammar parses them where an expression, a name or a statement
  may stand.
- **Parsed per language.** The pattern is parsed with the grammar of each language searched (the grammars of
  `anchors.TS_LANGS`, plus Python's). A fragment that is not a whole program on its own (a Java call or `return`)
  is parsed inside the smallest wrapper that parses without an error (a statement with `;`, a class body, a method
  body); the pattern's node is the innermost one spanning exactly its text (or its text plus the `;` the wrapper
  added). A language whose grammar cannot parse the pattern is not searched and is named
  (`not_searched.pattern_not_parsed`); a pattern that parses nowhere, or is only a metavariable, is refused
  (exit 2).
- **Matching.** Same node kind and the same children, a leaf the same text; commas and semicolons between
  children are not compared (so `foo($A, $$$REST)` matches `foo(1)`, as in ast-grep), except a comma after a
  comma or an opening bracket (a hole: `[1, , 2]` does not match `[$A, $B]`); comments in the code are skipped.
  `--lang typescript` (and a rule's `language: typescript`) includes the `.tsx` files, which have a grammar of
  their own. `$$$` backtracks. Nested matches are all reported.
- **Evidence.** Each match is `statically_verified`: its `at` (file:line), end line, language, the matched text
  and the captures, read from the file on disk now (the index is not used, so nothing is stale). It is about shape
  only: names are not resolved, which the output says.
- **Bounds.** A time bound per file (2 s; a file past it is listed in `not_searched.timed_out`) and per search
  (60 s; the files left are counted), files over 1 MB skipped and counted, `--max-results` (200) with
  `truncated`. A file that lacks a literal leaf of the pattern (a name, an operator, a bracket) cannot match and
  is not parsed: `_ts_parser($A)` over Verinoda's own `verinoda/` folder takes about 1.7 s for 239 files.
- **Rule files.** `--rule FILE` reads YAML rule files, one rule per document (`---` between them): `id`,
  `language`, `pattern` (or `rule: {pattern: ...}`, the ast-grep shape) and `message`. PyYAML is not a
  dependency, so a small reader takes the subset rules need (nested mappings, plain or quoted scalars, `|`/`>`
  blocks; a `#` inside quotes is text; a BOM is skipped). With `--rule`, a first argument that names a path is a
  path, not a pattern. A rule key that would change what matches (`not`, `inside`, `has`, `constraints`, ...) is
  refused rather than ignored, and a rule's `language` is checked as `--lang` is (exit 2).
- **CLI only.** No MCP tool: the core profile stays at five tools; `run_tool` or the full profile can reach it
  later.

## Measured

- `verinoda grep-ast '_ts_parser($A)'` over this repository: 915 files of 15 languages read, 6 matches, 23 s
  before the literal-leaf prefilter; with it, the `verinoda/` folder (239 files) in 1.7 s with the 4 matches
  there (`anchors.py:407`, `grep_ast.py:109`, `index.py:1487`, `review_rules.py:1089`). `anchors._ts_parser(...)`
  in `entail.py` is not a match: the pattern has no receiver.

- Review round: fixed a rule file's relational keys being dropped silently (now refused), a sparse array
  matching a two-element pattern, a rule language not checked, a quoted YAML value cut at ` #`, `.tsx` left out
  of `--lang typescript`, the time-budget count including files no pattern could search, PHP patterns parsed
  as inline text (so PHP never matched; now parsed after `<?php`), paths outside the project or `./src` with
  `--repo` searching nothing (now normalised or refused, and a missing `--repo` folder is refused), blank or
  comment-only patterns and broken patterns with no file to search not refused, and a rule file's BOM.
  `$NAME` inside strings and the lack of an escape are now documented as limits. Kept: exit 1 when nothing
  matches (exit 2 stays for a bad pattern or rule file, as in grep and ast-grep, so a script can tell them
  apart).

## Limits

- Shape only: no name resolution, no types (`foo(...)` matches every `foo`).
- No constraints or relational rules (`inside`, `has`, `not`, `regex` on a metavariable) and no fixes or
  rewrites; a rule is a pattern.
- A pattern parses only where its language allows it standalone or in one of the wrappers: a Java class member
  pattern with metavariables in odd places, or a statement with a trailing `;` in Python, may not parse or may not
  match; the language is named when it does not parse.
- Node kinds must be equal: the same text parsed in a different context can give a different kind (a TypeScript
  identifier in a type position is a `type_identifier`).
- The YAML reader is a subset: no lists, anchors or flow collections in rule files.
- `$NAME` is a metavariable wherever it stands, inside a string literal too (`print("$A")` matches any one-part
  string), and there is no escape: a literal `$_GET`, or an upper-case `$NAME` in PHP or JavaScript, cannot be
  searched.

## Upgrading note

New command `verinoda grep-ast PATTERN [PATH ...] [--lang L] [--rule FILE] [--max-results N] [--json]`:
structural search with `$A` / `$$$REST` metavariables over Python, Java, TypeScript and the other tree-sitter
languages the index reads; exit 0 with matches, 1 without, 2 on a bad pattern or rule file. No MCP tool was
added, so the tool count in UPGRADING does not change.

## Tests

`tests/test_grep_ast.py`: one pattern found across Python, Java and TypeScript with captures (`$$$` empty,
comments skipped, nested calls, Markdown not read); repeated and anonymous metavariables; a language whose
grammar cannot parse the pattern is named, a Java `return` parsed inside a method body; refusals (only a
metavariable, unknown language, unparsable pattern); `--lang` and paths; the bounds (time per file, max results,
size); YAML rule files (block scalar, nested `rule.pattern`, language, message, missing pattern); the CLI's JSON
and exit codes and `--rule` with a path argument. Review round: relational rule keys refused, a sparse-array
hole compared, a rule's language checked, a quoted value with ` #` and a BOM, `.tsx` under `typescript`, the
budget count, PHP, blank and comment-only patterns and no files to search, CLI paths outside the project, `./web`
from another folder and a missing `--repo`.
