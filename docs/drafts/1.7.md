## Why

Verinoda had ranked retrieval (`query`), structural search (`grep-ast`) and the MCP Grep hook, but no plain exact or
regular-expression search: an agent or a user looking for every `TODO`, every `cap_response(` or every `class
\w+Error` had to walk every file. Zoekt, Cursor and Moderne answer such searches from a trigram index. On a
repository of a few thousand files a walk costs seconds; most of that is reading files that cannot match.

## Decisions

- New command `verinoda search PATTERN [PATH ...] [-i] [-F] [--max-results N] [--rebuild] [--json]`, module
  `verinoda/trigram.py`. No MCP tool (the Grep hook and `query` cover agents; a tool can follow).
- **The index** is `.verinoda/index/trigram.db` (SQLite, derived and disposable like `search.db`): for every text file
  (git's tracked and untracked-not-ignored files, or a walk outside git; no NUL byte in the first 8 KiB; at most
  2 MB) its sorted array of distinct byte trigrams with ASCII letters lowered (24-bit integers), and for every
  trigram the sorted list of files holding it. Trigrams are computed with numpy (already a dependency).
- **Freshness without a daemon:** every search lists the files (`git ls-files -co --exclude-standard`), reads their
  sizes and modification times a directory at a time (`os.scandir` on 8 threads: on Windows the listing carries
  both, so no file is opened) and re-indexes the files that differ, dropping the ones gone. A changed file's new
  trigram array is diffed with the stored one and only the postings that differ are rewritten, in one transaction.
  The first search builds the whole index.
- **What a pattern requires** (`required`): the parsed expression (`re._parser`) becomes an AND/OR tree of literal
  runs of at least three bytes that every match must contain: a sequence ANDs its parts, a repeat with a minimum of
  one requires its body, an alternation requires one of its branches (nothing when any branch requires nothing),
  and classes, `.`, anchors, backreferences and lookarounds break a run. Candidates are the files whose postings
  hold every trigram of a required literal.
- **Soundness over speed:** the expression, not the index, decides every match; the index only picks the files to
  read. Case-insensitive patterns (`-i`, `(?i)`, `(?i:...)`) require only ASCII runs without `i`, `k` and `s`,
  because Python's case folding matches those to `İ`, `ı`, the Kelvin sign and the long s (measured on Python 3.13
  over every code point); a non-ASCII character or U+FFFD breaks a run under any flags where its bytes may differ.
  Files are read as UTF-8 with replacement; `^`/`$` work per line (multiline).
- **Output:** each match is `path:line` with the line's text (cut at 300 characters), `status: observed` - what the
  file says now, like a grep - plus the number of files indexed and read, whether the pattern narrowed the files,
  and the time spent per stage. Exit 0 with matches, 1 with none, 2 on a bad pattern or argument.

## Measured

On this repository (2,710 files, 45 MB of text), with the full test suite and three review agents running on the
same machine:

- building the index: 11 s (the first version, with Python sets, took 65 s); `trigram.db` is 56 MB;
- a search with nothing changed spends 0.35 s keeping the index fresh (git's file list about 0.18 s, the directory
  scan 0.08 s);
- `def changes_vs_base`: 10 of 2,710 files read, 0.39 s in total (a walk: 2.7 s);
- `cap_response|MAX_FILE_BYTES`: 58 files read, 0.55 s (walk 3.3 s);
- `todo|fixme` with `-i`: 56 files read, 0.68 s (walk 6.0 s);
- `class \w+Error\b`: 731 files read (`class ` and `error` are common), 1.1 s (walk 2.7 s);
- `sipariş` with `-i`: only `par` is required (`i`, `s` and `ş` fold), 1,683 files read, 3.9 s (walk 4.8 s);
- `\w+`: nothing required, every file read, 9.6 s (walk 7.9 s).

Every pattern returned exactly the matches the walk found (the benchmark compared the totals; the tests compare
the sets of `path:line`).

## Limits

- Text files only: binary files and files over 2 MB are neither indexed nor searched.
- A pattern without a literal run of three characters every match must hold reads every file: correct, and no
  faster than a walk. Case-insensitive searches narrow less (the folding letters break runs).
- The freshness check costs about 0.35 s on 2,700 files each search; a file changed while a search runs may be
  read in either version. Size and modification time decide whether a file changed (a rewrite that keeps both is
  not seen until one differs).
- The index takes about 1.2 times the size of the text it covers.

## Upgrading note

New command `verinoda search`: exact and regular-expression search narrowed by a trigram index that it builds on
first use in `.verinoda/index/trigram.db` (disposable; delete it or pass `--rebuild` to start over). No MCP tool
changes.

## Tests

`tests/test_trigram.py`: the requirement tree (sequences, classes, alternations with and without a requirement-free
branch, optional and repeated groups, short literals); case folding (`i`, `k`, `s` and non-ASCII letters break
literals under `-i`, `(?i)` and not without it, with the folding matches themselves checked); search results equal
a walk's `path:line` set for literal, class, case-insensitive, non-ASCII, alternation, anchored and unnarrowed
patterns in a repository whose path has a space and `ş`; binary and git-ignored files left out; path scope; an
incremental update after an edit, a delete and a new file (the old content leaves the postings); a rebuild; CLI exit
codes; pathological patterns stay bounded.
