# 5.1 Session dedup (draft for DESIGN.md; next free D-number)

## Why

An agent asks `project_query` several related questions in one session; the same top passages come back each
time, and every repeat spends the answer's character budget (and the agent's context) on text it already has.
Probe and Ref skip passages a session already returned. Here the MCP server remembers what it printed.

## Decisions

- **The session is the MCP server process** (one `AtlasTools`): an agent's session talks to one server. A new
  server, the CLI and `analyze` are not affected.
- **Text answers only, and only what was printed.** The server remembers, per file, the line windows its
  text answers printed (not an item's whole span: a long class shown by two windows is remembered as those two
  windows), and only the windows still in the answer when it was sent (a section the budget note pushed out is
  not remembered). In a later answer, an item whose whole span those windows cover is not printed again; within
  a longer item, a window printed before is not printed again (its header says so when nothing new is left). The
  JSON format is data and returns every item.
- **Never hidden without saying where.** The items not repeated are listed, grouped by file with their line
  ranges, near the top of the answer, before any section: the budget note at the end can never push the list
  out.
- **Changed files are new again.** Each remembered window carries its file's stat (mtime and size) when it was
  printed; a file that changed since is forgotten, and its passages are printed again. A file modified within the
  server's racy window (the one the answer memo uses) is not remembered at all.
- **The kept answer is the result, not its text.** The answer memo (D44-era) now keeps the retrieval result
  and renders it for each call with the session's memory, so a repeated question still costs no retrieval.
- **Off switch**: `VERINODA_QUERY_DEDUP=0` in the server's environment (tests that compare two answers use it).
  No new MCP argument: the core menu is near its size limit, and the listed locations already let the agent get
  the text again (by reading the file or `node_inspect`).

## Measured

Tests: the same question twice in one session prints none of the first answer's sections the second time and
lists them; a second server prints them all; an edited file's passages come back.

Review round (two reviewers): fixed whole spans remembered for items printed in part, sections the budget note
pushed out remembered as returned, the "already returned" line dropped by the budget (now at the top, grouped by
file, never cut by the note), a list cut at twelve locations, and same-tick edits keeping their stamp.

## Limits

- An agent whose context was compacted loses the passages it was given; the answer only lists their locations.
- The list of items not repeated is clipped at 700 characters on a very long session.
- The memory lives as long as the server process and grows with the number of items printed (a few bytes each).

## Upgrading note

`project_query` (MCP, text format) no longer repeats passages it already printed in the same server session; it
lists them by location instead. Set `VERINODA_QUERY_DEDUP=0` to turn this off. JSON answers and the CLI are
unchanged. The MCP tool count is unchanged.

## Tests

`tests/test_mcp.py`: a repeated query in one session returns only new passages and lists the rest; a new server
returns them all; a changed file's passages are new again; JSON is not deduplicated; the stdio round trip's
second identical call; the memo tests with dedup off; only windows still in a budget-cut answer are remembered;
the list comes before any section; a long item seen in part is not hidden.
